# 2026-09-20 ネットワーク・Web スタック・TLS の基礎を理解する

前日に構築した環境(VPC / EC2 / nginx / systemd / Let's Encrypt)を題材に、「なぜそう動くのか」を理解した記録。
この日に理解した内容が中心で、実装(Elastic IP の取得と Route 53 への紐付け)は自分でやり直す予定。

## 1. ネットワーク(VPC)

- **パブリック/プライベートを決めるのはルートテーブル**。`0.0.0.0/0 → IGW` があるサブネットがパブリック。
- IGW は、パブリックIPとプライベートIPの 1:1 NAT を行う。EC2 の OS から見えるのはプライベートIPだけ。
- ルートは最長一致。`0.0.0.0/0` は「他のどれにも当てはまらない宛先」の受け皿。
- ルートテーブルは「道案内」、SG は「検問所」。役割が違う。ルートテーブルに inbound/outbound の区別はない。
- SG はステートフル(戻りの通信は自動で許可)、許可のみ書ける。SG 参照で「この SG に属するものだけ」と指定できる。
- 同じ `0.0.0.0/0` でも、ルートテーブルでは「全宛先」、SG の inbound では「全世界から許可」で意味が違う。
- 接続できないときの見分け方: **タイムアウト**は途中で捨てられている(SG など)、**refused** は届いたが待ち受けがない。
- TCP 3-way handshake(SYN → SYN-ACK → ACK)。ポートが閉じていると RST が返る。
- サブネットと ENI は起動後に変更できない。最初の EC2 をプライベートサブネットに作ってしまい、作り直した(失敗から学んだ点)。
- 未確認のまま残した点: プライベートサブネットの EC2 に、外から SYN が届くかどうか。確実に言えるのは「返事が外に出られない」ことだけ。

## 2. Web スタック

- **nginx** は TLS の終端とリバースプロキシ。`proxy_pass http://127.0.0.1:8000` でアプリへ渡す。
- **uvicorn** は ASGI サーバ(待ち受けとHTTPの解釈)、**FastAPI** はアプリ(どのURLでどの関数を呼ぶか)。役割が別。
- HTTP は書式のあるテキスト(リクエスト行・ヘッダ・空行・本文、ステータスコード)。`curl -v` の `*` `>` `<` が読める。
- `/healthz` は標準ではなく自分で決めた慣習。
- **プロセスと関数の違い**: プロセスは systemd(`Restart=always`)で常駐、関数は起動時にメモリに載って呼ばれるだけ。答えは呼ばれるたびに計算する。60秒キャッシュだけが例外。
- 502 Bad Gateway の原因: 手動起動した uvicorn がポート 8000 を握っていて、サービス側が起動できなかった。`pkill` で止めてサービスを再起動して解消。

## 3. TLS と鍵

整理して理解できた点:

1. **鍵は役割が2種類ある**
   - 長く使う本人確認用の鍵ペア(SSH なら EC2 のキーペア、HTTPS なら certbot の `privkey.pem` と証明書)。
   - 接続ごとに作る使い捨ての鍵交換用ペア。
2. 流れ
   - OS の乱数から「秘密の数」を作る(接続ごと)
   - 秘密の数と公開式から「公開の値」を作り、お互いに送り合う
   - 自分の秘密の数と相手の公開の値から、両者が同じ「共通の秘密」を得て、共通鍵にする
   - 共通鍵でデータを暗号化・復号する
   - 本人確認として、サーバが長く使う鍵で公開の値に署名する(中間者攻撃の対策)
3. 共通鍵は通信路に流れない。式は公開でも、逆算できない(一方向)ので安全。
4. 公開鍵は秘密鍵から導けるが、逆はできない(`ssh-keygen -y`)。
5. 鍵ペアの使い方は2つ: 公開鍵で暗号化して秘密鍵で復号、秘密鍵で署名して公開鍵で検証。
6. 証明書は「公開鍵 + CA の署名」。CA の公開鍵はブラウザ/OS に最初から入っている。
7. 乱数は OS の暗号用乱数を使う。Python の `random` はシードで再現できるので暗号には使えない。
8. 総当たりは、ビットが2増えるごとに約4倍。256 ビットは現実的に不可能。
9. 式が公開でも安全という考え方(ケルクホッフスの原理)。
10. 前方秘匿性: 長期鍵が漏れても、過去の通信は復号できない。

面接で話すときの一言:
「TLS は、使い捨ての鍵交換で共通鍵を作ってデータを暗号化し、サーバ証明書で相手が本物であることを確認する仕組みです。」

## 4. Let's Encrypt

- HTTP-01 と DNS-01 の違い。DNS-01 を選んだ理由: SG を自宅IPのみに保てる、自動更新もできる。
- ACM の通常の公開証明書はエクスポートできない(ALB / CloudFront 向け)。EC2 上の nginx では使えない。
